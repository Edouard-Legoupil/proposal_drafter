# Native Azure CrewAI Connection Design

## Goal

Remove LiteLLM from the application and connect CrewAI directly to Azure AI using CrewAI's native Azure provider, while retaining the existing API-key environment variables.

## Architecture

Chat completion will use `crewai.llms.providers.azure.completion.AzureCompletion` explicitly. This provider subclasses CrewAI's `BaseLLM` and calls the Azure AI Inference SDK directly, including native tool calling and structured responses. Explicit construction prevents CrewAI from selecting a LiteLLM adapter.

Application-managed embeddings will use the official `openai.AzureOpenAI` client directly. A shared helper in `backend/core/llm.py` will own client construction and expose a small embedding function so callers do not manipulate provider configuration dictionaries.

CrewAI knowledge-source embedding configuration will remain Azure-based because CrewAI's Azure embedding provider already uses the OpenAI SDK rather than LiteLLM.

## Configuration

The migration preserves the existing variables:

- Chat: `AZURE_OPENAI_ENDPOINT`, `AZURE_OPENAI_API_KEY`, `OPENAI_API_VERSION`, `AZURE_DEPLOYMENT_NAME`
- Embeddings: `AZURE_OPENAI_ENDPOINT_EMBED`, `AZURE_OPENAI_API_KEY_EMBED`, `AZURE_OPENAI_API_VERSION_EMBED`, `AZURE_EMBEDDING_DEPLOYMENT_NAME`

Missing required values fail during configuration with names only; secrets are never logged. API-key authentication remains temporary and can later be replaced with Entra ID without changing CrewAI agents.

## Error Handling

Azure SDK exceptions propagate to the existing application error and circuit-breaker layers. Embedding callers retain their current per-chunk logging and failure behavior, but provider configuration and secret values are excluded from errors generated by application code.

## Dependency Policy

`litellm` will be removed from `backend/requirements.txt` and all application imports and logger references. CrewAI will be constrained to a release containing its native Azure AI Inference provider and installed with the `azure-ai-inference` extra. A policy test will fail if LiteLLM is reintroduced anywhere in backend runtime code or requirements.

## Verification

Tests will prove that:

- the configured CrewAI model is an `AzureCompletion`, not a LiteLLM-backed `LLM`;
- existing endpoint, deployment, API version, timeout, and key settings reach the native provider;
- embeddings call `AzureOpenAI.embeddings.create` with the configured deployment;
- knowledge search and ingestion consume the direct embedding helper;
- LiteLLM is absent from runtime imports and requirements;
- backend regression, lint, Bandit, and dependency audit remain green.
